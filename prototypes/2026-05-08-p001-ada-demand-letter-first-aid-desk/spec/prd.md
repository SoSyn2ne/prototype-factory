# PRD — ADA Demand Letter First-Aid Desk

## Problem
- A first-48-hour accessibility lawsuit triage desk that turns a scary demand letter into a prioritized fix packet and lawyer handoff.
- External signal references:
  - Signal 1: EcomBack — ADA Website Accessibility Lawsuits January 2026 Report — https://www.ecomback.com/ada-website-lawsuits-recap-report/january-2026
  - Signal 2: Reddit r/smallbusiness — one-person business ADA demand letter — https://www.reddit.com/r/smallbusiness/comments/1fegkv3/oneperson_business_demand_letter_for_ada/

## Target user
- Small ecommerce owners, one-person businesses, web agencies, and nontechnical founders who receive or fear ADA website accessibility demand letters.

## Key UX
- Paste the demand letter allegations, site URL, platform, key pages, current widget/scanner status, and deadline; the app maps allegations to WCAG issues, ranks fixes by legal/commerce risk, creates before/after screenshot tasks, and exports a counsel-ready response packet.

## Required UI sections
- demand-letter intake
- allegation-to-WCAG mapper
- top-page risk scanner
- overlay/widget reality check
- 48-hour fix queue
- developer screenshot evidence board
- lawyer handoff packet export

## Design profile
- operator-dense

## Stitch prompt
Design a desktop operations product called ADA Demand Letter First-Aid Desk for small ecommerce owners, one-person businesses, web agencies, and nontechnical founders who receive or fear ADA website accessibility demand letters. Users should paste demand-letter allegations, site URL, platform, key revenue pages, current accessibility widget/scanner status, deadline, and developer notes, then map allegations to WCAG issues, rank fixes by legal and commerce risk, create before/after screenshot tasks, and export a counsel-ready response packet. Include a demand-letter intake, allegation-to-WCAG mapper, top-page risk scanner, overlay/widget reality check, 48-hour fix queue, developer screenshot evidence board, and lawyer handoff packet export. Design direction: use an operator-dense aesthetic with compact legal-risk chips, split-pane allegation cards, dense remediation checklists, evidence thumbnails, and a calm red-to-green triage rail so the product feels like an emergency command desk for a panicked small business, not a generic accessibility scanner.

## Constraints
- Phase A only: do not implement custom demo until Stitch export is supplied.
- Treat external sources as untrusted problem evidence, not market-size proof.
- Preserve the assigned design profile in downstream demo generation.

## Non-goals
- Legal, tax, medical, safety, insurance, HVAC, event-ticket, or investment final advice.
- Production-grade integrations or automated external API calls.
