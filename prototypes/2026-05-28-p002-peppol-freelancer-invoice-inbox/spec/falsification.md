# Falsification checklist (5–7)

1. Existing local invoicing tools already solve freelancer Peppol onboarding simply.
2. Freelancers delegate all structured invoicing to accountants and will not use a self-serve inbox.
3. Country-specific rules make a generic prototype too vague to be credible.
4. Users cannot understand UBL/XML validation even with plain-language translations.
5. A read-only readiness tool has no willingness-to-pay without actual Peppol sending.
6. Accountants prefer client portals inside their existing practice software.
7. The UI becomes too dense for a solo freelancer audience.
