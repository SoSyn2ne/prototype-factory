# Falsification checklist (5–7)

1. If operators still keep separate terminal notes while using the demo, what critical information is the UI failing to capture in one pass?
2. If a maintenance session is interrupted and the restored draft feels unreliable after reload, does `localStorage` persistence actually solve the continuity problem?
3. If the generated text log is routinely edited heavily before sharing, is the export format or structure too weak to be useful?
4. If the fixed 7-step checklist does not match how operators sequence real GPU upkeep, is the concept too rigid even for a prototype?
5. If the timer is ignored during most sessions, does elapsed-time tracking add noise instead of operational value?
6. If risk flags are checked inconsistently or not at all, are they poorly chosen signals rather than meaningful incident breadcrumbs?
7. If the UI cannot support maintenance comfortably on a laptop-sized viewport next to terminal windows, does the layout fail the actual operating environment?
