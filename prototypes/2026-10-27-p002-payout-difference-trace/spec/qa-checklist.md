# QA checklist — 쇼핑몰 정산 차이 추적

## 현재 산출물
meta.json의 ID·날짜·repoPath·두 작성자 출처와 commercial.json의 v1 계약을 확인한다. 가격·고객 확보·지불의사·반복 결제는 미확인으로 남겨야 한다. HTML은 정적 예시임을 분명히 표시하며 입력·실행 버튼·은행 로그인·네트워크 호출·회계 쓰기 기능을 포함하지 않는다.

## 향후 기능 검증
서로 다른 통화/기간/정의, 별도 결제 경로, 부분 환불, 원거래 키 없음, 중복 행, 빈 수수료, 조정과 뒤늦은 입금을 담당자의 기준과 대조한다. 미설명 항목이 임의 분류되지 않고 모든 설명을 원본 행으로 추적할 수 있는지 확인한다. 실제 장부·은행·스토어 불변과 수동 복귀를 검사한다.

## 주장 검증
원문의 불일치를 실제 미지급금이나 세금 오류로 확정하지 않고 특정 Q4 작업을 매월 소요시간으로 확대하지 않는다. 향후 유료 실증 판정에는 합의 후 첫 실제 수금·같은 명세의 확인 시간 개선·잘못된 연결/추정 분류 비증가·담당자 검토가 모두 필요하다. 수금 없이 효용만 확인되면 업무 타당성 관찰로만 기록하고 만족·재사용·재결제는 별도로 둔다. 현재 수금·기능 통과 기록은 없다.
