# 쇼핑몰 정산 차이 추적

## 현재 범위
한 스토어의 정산명세 한 건과 대응 거래 내보내기를 읽고, 순입금의 구성·대조 범위·아직 설명되지 않는 차이를 사람이 확인할 자료로 정리하는 작은 프로그램의 기획이다. 현재는 설계 문서와 **설계 예시 · 실제 파일 처리 미구현**인 정적 HTML만 있다. 정산 계산·파일 읽기·은행/회계 연동·자동 분개는 없다.

## 확인한 문제와 제안의 경계
[johnmay1021의 직접 경험](https://www.reddit.com/r/quickbooksonline/comments/1sevrzs/shopify_payout_reconciliation_is_anyone_doing/)은 QuickBooks Online에 들어온 순입금을 매번 수동 분리하고 가끔 실수한다고 한다. [dyeshadb의 원글·후속 답변](https://community.shopify.com/t/payments-from-shopify-only-do-not-match-total-sales-from-shopify-only/397749)은 Q4 매출·입금 보고서를 주문별로 대조하고 지원팀에 문의한 사례다. 확인일은 2026-10-27이다. Reddit 게시일은 검색 색인상 2026-04-07이며 본문 절대 날짜는 미확인, 포럼 원글은 2025-02-28·후속은 2025-03-01이다. 실제 미지급금이나 작성자의 회계 해석은 검증하지 않았다.

## 다음 실증과 미확인 사항
사전 동의한 운영자 또는 기장 담당자 한 명이 익명화한 한 스토어·정산명세 한 건을 기준으로 수작업 설명을 만든다. 거래 파일의 기간·통화·기준이 다르면 대조 불가로 남기고, 차이를 임의로 세금·수수료·누락 매출로 확정하지 않는다. 구매자·접근·가격·월별 빈도·지불의사와 기존 도구 대비 이점은 미확인이다.
