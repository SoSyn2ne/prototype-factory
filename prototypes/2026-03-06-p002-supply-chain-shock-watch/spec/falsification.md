# Falsification checklist (5-7)

1. If operators cannot explain why Shock Score changed after an edit, does the scoring model fail the transparency requirement?
2. If filtering to `SPOF only` hides too much context for action planning, is the table interaction model wrong?
3. If mitigation suggestions repeat generic advice that does not map to filtered rows, is the recommendation logic too shallow?
4. If users still need a separate spreadsheet to find impacted products, does the dependency view fail its core purpose?
5. If score changes are too small to prioritize incidents, are the criticality and SPOF weights miscalibrated?
6. If analysts cannot complete triage in under 3 minutes during testing, is the interface too dense or workflow too long?
