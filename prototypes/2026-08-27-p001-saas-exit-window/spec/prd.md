# PRD — SaaS Exit Window

## Problem
- Small teams can lose affordable vendor access before exports and automations are proven portable.

## Target user
- Bootstrapped teams using one critical SaaS.

## Arrival path
- Live source signal, operator search, or peer share.

## Business / validation route
- Test five target users completing the core loop with realistic local data.

## Core loop
- Watch vendor change → map jobs → rehearse export → verify replacement → issue exit receipt.

## First screen
- Watched vendor, plan, last verified export, and Run 15-minute exit rehearsal.

## Key screens
- Vendor watch; dependency map; export rehearsal; automation breakpoints; replacement shortlist; exit receipt.

## Interaction rules
- A job is ready only when its sample export opens, required fields pass, and dependencies have owners.

## Output artifact
- Evidence-stamped exit receipt.

## Share / return loop
- Quarterly rehearsal reminder and founder/ops handoff.

## Constraints
- Time: one-session prototype loop under 15 minutes.
- Budget: local mock data; no paid APIs.
- Platform: responsive web/mobile concept appropriate to the interaction.

## Non-goals
- No production integration, automated external action, or custom demo in Phase A.

## Success metrics
- 80% of five testers explain the core rule in 15 seconds and finish the main loop without help.

## QA / screenshot criteria
- Show price-change, export failure, missing field, and verified states; readable at 1440px and 390px.

## Design profile
- operator-dense

## Theme

## Source signal references
- S1 Ask HN self-serve retreat; S2 live website-change feed.
