# QA checklist

## Happy path
- Open the prototype spec and understand the main decision loop within one pass.
- Confirm the required UI sections support the core workflow: Compare claim-versus-cash scenarios, see deductible pain against future premium risk, and leave with one defensible next move before contractors or adjusters control the story.

## Edge cases
- Validate that emotionally sensitive states still feel clear and non-chaotic.
- Check that the design profile (financial-analyst) stays visible without overpowering usability.

## Acceptance verification
- Theme is explicitly labeled as 자산 방어.
- Stitch prompt is copy-ready and includes explicit design direction.
- Meta/spec text matches the daily idea card with no placeholders.
