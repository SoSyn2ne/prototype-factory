# Falsification checklist

1. The first screen reads like a generic dashboard instead of email triage + policy-backed response helper.
2. A target user cannot identify the next action within 5 seconds.
3. The required UI sections are missing: Complaint inbox with tone/severity tags; Policy anchor selector; Evidence and prior-contact log; Reply draft with warmth/firmness slider; Admin escalation summary.
4. The design direction does not match calm-consumer.
5. The prototype depends on source claims as market-size proof instead of treating them as problem evidence.
6. The workflow duplicates one of the last 7 PF batches without a new user, trigger, data source, or interaction mechanic.
7. The final screen lacks a shareable output, packet, receipt, or result tied to: Departments can share reply templates and policy anchors across grade teams.
