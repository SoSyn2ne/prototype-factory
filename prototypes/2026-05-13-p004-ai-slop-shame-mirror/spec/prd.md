# PRD — AI Slop Shame Mirror

## Problem
- A playful self-audit booth that tells creators whether a post feels like disposable AI slop or something a human would actually share.
- Search/community evidence suggests this is a live pain, not a generic dashboard rename.

## Target user
- Creators, founders, newsletter writers, indie makers, educators, and marketers who use AI drafts but fear audience embarrassment or “slop” backlash.

## Key UX
- Paste a draft post, landing hero, short-video script, newsletter intro, or product update; the app highlights generic phrases, fake-depth signals, over-polished tone, missing lived detail, and shareability hooks, then gives a before/after “less slop, more soul” makeover card.

## Required UI sections
- draft paste stage
- slop smell score
- generic phrase highlighter
- human-detail injection prompts
- audience cringe meter
- before/after makeover card
- shareable anti-slop badge

## Design profile
- `playful-experimental` — reflected in the Stitch prompt and visual direction.

## Stitch prompt
Design a playful creator self-audit product called AI Slop Shame Mirror for creators, founders, newsletter writers, indie makers, educators, and marketers who use AI drafts but fear audience embarrassment or “slop” backlash. Users should paste a draft post, landing hero, short-video script, newsletter intro, or product update, then highlight generic phrases, fake-depth signals, over-polished tone, missing lived detail, and shareability hooks, and generate a before/after “less slop, more soul” makeover card. Include a draft paste stage, slop smell score, generic phrase highlighter, human-detail injection prompts, audience cringe meter, before/after makeover card, and shareable anti-slop badge. Design direction: use a playful-experimental aesthetic with bold mirror-booth composition, cheeky but readable warning stickers, neon annotation marks, expressive cringe meters, and a highly shareable makeover card so the product feels like a memorable portfolio experiment about reputation anxiety, not a bland grammar checker.

## Constraints
- Time: Phase A spec/scaffold only; do not implement custom demo yet.
- Budget: Use Stitch export workflow for Phase B.
- Platform: Web prototype, desktop-first unless consumer flow benefits from responsive cards.

## Non-goals
- Do not claim legal, medical, tax, or financial certainty.
- Do not integrate live paid APIs in Phase A.

## Success metrics
- A user understands the painful trigger within 5 seconds.
- The main workflow is clear from intake to analysis to action/export/share.
- The UI can be built from the Stitch prompt without additional explanation.
