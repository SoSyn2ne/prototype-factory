# PRD — Pose Telephone Relay

## Problem
- Camera party games need a rule understood instantly and failures worth sharing.

## Target user
- Friends, classrooms, fitness groups, and streamers.

## Arrival path
- Live source signal, operator search, or peer share.

## Business / validation route
- Test five target users completing the core loop with realistic local data.

## Core loop
- Join → copy pose → pass silhouette → reveal mutation → share replay → rematch.

## First screen
- Room code, four slots, and oversized source-pose card.

## Key screens
- Room join; source pose; outline capture; relay chain; mutation reveal; replay; rematch.

## Interaction rules
- Only the previous player's three-second frozen silhouette reaches the next player.

## Output artifact
- Six-second vertical mutation replay.

## Share / return loop
- Share funny final mutation and rematch in one tap.

## Constraints
- Time: one-session prototype loop under 15 minutes.
- Budget: local mock data; no paid APIs.
- Platform: responsive web/mobile concept appropriate to the interaction.

## Non-goals
- No production integration, automated external action, or custom demo in Phase A.

## Success metrics
- 80% of five testers explain the core rule in 15 seconds and finish the main loop without help.

## QA / screenshot criteria
- Show missed body, two people, seated pose, strong mutation, privacy, and instant rematch on mobile.
