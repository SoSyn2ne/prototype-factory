# Assumptions (KNOWN / ASSUMPTION / UNKNOWN)

## KNOWN
- [KNOWN] Event-heavy domains (earnings, launches, macro prints) create daily triage pressure.
- [KNOWN] Unstructured notes make it hard to compare catalyst importance consistently.
- [KNOWN] A single-screen dashboard reduces context switching versus calendar + notes + spreadsheets.
- [KNOWN] Users need visible confidence framing to avoid treating all events equally.

## ASSUMPTION
- [ASSUMPTION] Users will accept simple impact/confidence labels if triage takes under 10 minutes.
- [ASSUMPTION] A ranked list is more actionable than a chronological list for research planning.
- [ASSUMPTION] Manual event curation is acceptable in early validation before automation.
- [ASSUMPTION] A static prototype can validate workflow desirability before building data integrations.

## UNKNOWN
- [UNKNOWN] Which weighting model best matches user-perceived event importance.
- [UNKNOWN] How many events per day users can score before abandoning the workflow.
- [UNKNOWN] Whether users need per-ticker grouping before global ranking.
- [UNKNOWN] How much explanation users need to trust triage order changes.
