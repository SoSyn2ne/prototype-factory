# 공급사 상품 변경 검수

## 현재 구현 범위

실행 경로는 [`/tools/supplier-review`](/tools/supplier-review)다. Prototype Factory에서 이 프로젝트의 상세 분석을 열고 검수 도구로 이동할 수 있다. 로컬 개발 서버를 실행한 경우 같은 경로에서 사용한다. 2026-11-12 로컬 브라우저에서 두 파일 업로드·비교·선별 승인·XLSX 다운로드와 주요 오류 상태를 확인했다. 전체 테스트 49개, 타입 검사와 프로덕션 빌드가 통과했다. 실제 고객 파일·실기기·고객의 Excel 앱 호환성은 미검증이다.

두 XLSX·CSV 파일을 브라우저에서 읽고 시트·상품 식별자·비교 열을 지정한다. 첫 비어 있지 않은 행을 헤더로 사용하며 별도 헤더 행 선택은 지원하지 않는다. 바깥 공백을 제거한 SKU가 정확히 일치할 때 값을 비교해 변경사항과 예외를 확인하고, 사람이 승인한 변경만 XLSX 검수 목록으로 내려받는다. Univer 오픈소스는 읽기 전용 비교 화면에, SheetJS는 파일 입출력에 사용한다. 파일 내용은 서버로 전송하지 않으며 상용 Univer Pro나 외부 계정 연결을 사용하지 않는다.

원본 파일은 변경하지 않는다. 다운로드는 **승인한 변경의 검수 목록**으로, Shopify에 바로 올리는 파일이나 원본 통합 문서 전체가 아니다. 값 중심으로 처리하며 서식·이미지·매크로 보존을 약속하지 않는다. 파일별 5MiB, 유효 시트별 상품 데이터 10,000행·100열, 통합 문서 전체 100만 셀, XLSX 압축 해제 내용 50MiB를 상한으로 둔다. 상품 표가 아닌 보조 시트는 이름과 제외 이유를 경고하며 유효한 상품 시트는 선택할 수 있다. 기존 `web/index.html`은 이전 정적 설계 예시다.

## 검수 규칙

- SKU는 바깥 공백을 제거한 뒤 정확히 같은 값만 연결하고 선행 0을 유지한다. 상품명·옵션·비슷한 코드로 추정하지 않는다.
- 비교 값의 바깥 공백은 제거하고 빈 값과 숫자 0을 구분한다. 엑셀 숫자는 반올림된 표시 문자열이 아닌 실제 저장값을 비교한다. 단위·통화가 같은지는 담당자가 확인한다.
- 중복 SKU와 빈 SKU가 있으면 해당 원본 행을 알리고 비교를 중단한다. 원본을 수정한 뒤 다시 비교한다.
- 한쪽에만 있는 상품은 추가·제외 후보로 표시한다. 누락만으로 삭제를 확정하지 않는다.
- 처음에는 모든 변경이 미승인이다. 파일·시트·열 매핑을 바꾸면 이전 승인을 폐기하고 다시 검토한다.
- 결과에는 승인한 항목의 식별자, 변경 종류, 비교 필드, 이전/현재 값과 원본 행 추적 정보를 담는다. 스토어 수정·자동 업로드는 수행하지 않는다.
- 다운로드는 비교 필드당 한 행이며 헤더를 제외한 최대 100,000행을 지원한다. 초과하면 내용을 자르지 않고 생성을 중단한다. 승인 상태는 유지하므로 승인 상품을 줄여 다시 내려받거나 비교 열을 줄여 재검토한다.

## 다음 실증과 미확인 사항

사전 동의한 운영자 한 곳의 익명 파일 한 쌍과 수작업 판정으로 검증한다. 변경·미변경·추가·제외·중복·빈 식별자를 모두 대조하고 실제 검수 시간과 예외 처리 시간을 기록한다. 구매자·자료 접근·가격·갱신 빈도·지불의사와 기존 도구 대비 이점은 아직 미확인이다. 유료 실증·재사용·재결제는 기능 구현과 별도로 확인한다.
