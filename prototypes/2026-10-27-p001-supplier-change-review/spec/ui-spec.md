# UI spec — 공급사 상품 변경 검수

## 정보 순서와 구성

기존 Prototype Factory 로고·홈 링크·한 가지 강조색·중립 표면을 유지한다. `/tools/supplier-review`의 첫 화면은 도구 이름과 파일 두 개 선택이 중심이다. 장식용 소개 영역을 늘리지 않는다. 기준/새 파일 구분, 지원 형식, 로컬 처리, 값 중심 결과의 범위를 파일 입력과 가까이 둔다.

파일을 읽은 뒤 각 시트·SKU·비교 열을 명시적으로 선택한다. 첫 비어 있지 않은 행이 헤더임을 안내하고 별도의 헤더 행 선택은 제공하지 않는다. 상품 표가 아닌 보조 시트는 이름과 제외 사유를 경고한다. 비교 후에는 변경 종류·식별자·필드·이전/현재 값·원본 행을 Univer 오픈소스 읽기 전용 표에 표시한다. 예외 사유와 승인 가능 여부는 색상만으로 구분하지 않는다. 추가·제외 후보는 변경 값과 혼동되지 않게 표시하고 중복·빈 SKU가 있으면 원본 행을 안내하고 비교를 중단한다.

승인은 표와 연결된 명시적 제어로 조작한다. 처음에는 모두 미승인이고 승인 개수와 다운로드 대상이 일치해야 한다. 다운로드 버튼에는 승인한 변경의 XLSX 검수 목록임을 밝힌다. 전체 원본 파일·스토어 업로드 파일로 표현하지 않는다. 제한적인 뷰포트에서도 파일 설정과 승인 조작에 접근할 수 있게 한다.

## 상태

- 준비 전: 파일 두 개와 비교 열을 선택하도록 안내한다.
- 읽는 중: 입력 중복 실행을 막고 현재 처리 상태를 표시한다.
- 읽기 실패/상한 초과: 해당 파일과 이유, 재선택 동작을 표시한다.
- 비교 전: 선택한 시트·헤더·SKU·비교 열을 확인한다.
- 변경 없음: 결과가 없다는 사실을 표시하고 다운로드를 유도하지 않는다.
- 검수 중: 변경·추가·제외 후보와 승인 불가 예외를 구분한다.
- 승인 없음/일부 승인: 정확한 승인 개수를 표시하고 승인 결과 다운로드 가능 여부를 맞춘다.
- 다운로드 실패: 승인 상태를 유지한 채 재시도를 제공한다.
- 다운로드 상한 초과: 변경 필드 100,000행 제한을 알리고 승인 상품 수나 비교 항목을 줄여 다시 시도하도록 안내한다. 결과를 일부만 내보내지 않는다.

## 이벤트와 접근성

파일·시트·매핑 변경 시 과거 결과와 승인을 초기화한다. 필터·선택과 승인 상태를 혼동하지 않는다. 파일 입력, 매핑 선택, 승인·취소·다운로드는 키보드로 사용할 수 있어야 한다. 한 개 h1, 입력 라벨, 오류 알림, 포커스 표시, 표와 연결되는 접근 가능한 검수 정보가 필요하다. Univer 화면은 브라우저 전용으로 로드하고 페이지를 떠날 때 인스턴스를 정리한다.

## 구현 경계

Univer OSS는 비교 표시, SheetJS는 XLSX·CSV 읽기와 승인 목록 XLSX 쓰기를 담당한다. SKU·비교 값은 바깥 공백을 제거하고 숫자는 실제 저장값으로 비교하되 원본 행 탭에는 파일의 표시 값을 보여 준다. 한 파일 5MiB, 유효 시트 데이터 10,000행·100열, 통합 문서 100만 셀, XLSX 압축 해제 내용 50MiB를 상한으로 둔다. 파일 내용은 서버로 보내지 않는다. 상용 Pro, 공동 편집, 외부 계정, 스토어 쓰기·자동 업로드는 범위 밖이다. 기존 `web/index.html`의 미리 작성된 행은 과거 설계 예시이며 실행 화면의 실제 처리 결과와 구분한다.
