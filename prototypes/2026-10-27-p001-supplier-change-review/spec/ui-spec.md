# UI spec — 공급사 상품 변경 검수

## 현재 설계 예시
첫 화면은 제목, “설계 예시 · 실제 파일 처리 미구현”, 비교할 한 쌍의 의미와 미리 작성한 검수 행이다. 예시 식별자·변경 값은 가상이며 실제 읽기·매칭 결과가 아니다. 기존 제품의 중립 표면·한 가지 강조색을 사용하고 작은 화면에서는 표만 가로 스크롤한다. 업로드·실행·저장·연결 버튼과 수치는 만들지 않는다.

## 향후 구성과 상태
정의 확인 → 원본/최신 파일 연결 → 식별자 대응 → 변경 값/근거/예외 표가 핵심이다. 준비 전, 읽기 실패, 정의 불일치, 식별자 예외, 검수 중, 사람이 확인한 목록을 별도 상태로 설계한다. “문제 없음”은 검토되지 않은 행을 포함할 수 없고 완전 자동 안전 판정으로 표현하지 않는다.

## 이벤트와 접근성
현재 허용 이벤트는 상세 분석·원문으로의 실제 링크 이동뿐이다. 향후 파일 처리를 만들 때 열 매핑 수정은 영향 행을 다시 검토하게 하고 모호한 값의 자동 확정을 막는다. 한 개 h1, 표 제목·열 머리글, 본문 대비와 키보드 포커스를 유지한다. 백엔드·Shopify 쓰기 API·결제는 범위 밖이다.
