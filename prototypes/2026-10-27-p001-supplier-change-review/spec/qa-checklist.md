# QA checklist — 공급사 상품 변경 검수

## 검증 상태

확인일은 2026-11-12다. 브라우저 검증은 로컬 개발 서버의 데스크톱과 390px 모바일 뷰포트 에뮬레이션에서 수행했으며 실제 모바일 기기·고객 파일·고객의 Excel 앱·운영 배포 검증으로 확대하지 않는다. site 전체 타입 검사(`tsc --noEmit`)와 `npm run build`는 종료 코드 0으로 통과했다. 프로덕션 빌드 후 전체 테스트 49개가 통과했고 실패는 0개다(신규 공급사 테스트 19개, 기존 테스트 30개). 초기 제한된 실행 환경에서는 localhost 접속 제한이 있었으나 승인된 일반 실행에서 코드 수정 없이 통과했다.

## 입력과 매핑

- [x] 실제 XLSX 파일 두 개 및 CSV 파일 두 개를 입력해 비교할 수 있다.
- [ ] 시트 선택과 SKU·비교 열 매핑 변경 조작을 브라우저에서 별도로 확인한다. 헤더는 첫 비어 있지 않은 행이며 임의 행 선택 기능은 없다.
- [ ] 한 파일만 선택한 상태, 비어 있는 파일·시트, 잘못된 형식, 읽기 실패에서 복구할 수 있다.
- [ ] 파일별 5MiB, 유효 시트별 상품 데이터 10,000행·100열, 통합 문서 100만 셀, XLSX 압축 해제 내용 50MiB 상한을 브라우저에서도 확인한다.
- [ ] 여러 시트, 상품 표가 아닌 보조 시트의 제외 경고, 쉼표·따옴표·줄바꿈 CSV와 한글 인코딩을 브라우저에서 확인한다.
- [x] 파일 교체 시 오래된 비교 결과와 승인이 폐기된다.
- [ ] 시트·열 매핑 변경 시에도 결과와 승인이 폐기되는지 브라우저에서 확인한다.

## 비교와 승인

- [x] 선행 0이 있는 상품코드 001을 보존하고 해당 상품을 선택·승인할 수 있다.
- [x] 중복 001 코드 입력 시 중복된 원본 행을 알리고 비교를 중단한다.
- [ ] 빈 SKU의 원본 행 오류와 바깥 공백 제거 후 중복 판정을 브라우저에서 확인한다.
- [ ] 빈 값과 0, 표시 형식에 가려진 실제 숫자 차이를 브라우저에서 확인한다. 값과 SKU의 바깥 공백은 제거하는 규칙이다.
- [x] 샘플의 변경 후보 4개와 미변경 1개가 예상 결과와 일치한다.
- [x] 동일한 두 파일에서 변경 없음 상태를 표시한다.
- [x] 최초 승인 항목이 없고 001만 승인한 결과에서 다른 상품을 제외한다.
- [ ] 개별 승인 취소 후 취소한 항목이 다운로드에 남지 않는지 브라우저에서 확인한다.

## 출력과 데이터 경계

- [x] 파일 교체로 승인이 초기화되면 다운로드할 승인 결과가 남지 않는다.
- [x] 실제 다운로드한 XLSX를 다시 읽어 승인한 001 항목과 이전/현재 값, 이전/새 원본 행이 포함된 7개 열을 확인한다.
- [ ] 고객의 Excel 앱에서 내려받은 파일을 열고 호환성을 확인한다.
- [ ] 수식처럼 보이는 문자열의 비실행과 원본 불변·파일 내용 외부 비전송을 브라우저에서 별도 확인한다.
- [x] 다운로드가 승인한 변경 검수 목록임을 표시하고 스토어 업로드·원본 수식/서식 보존을 약속하지 않는다.
- [ ] 다운로드 실패 후 승인 상태를 유지하고 재시도할 수 있다.
- [x] 변경 필드가 100,000행을 넘는 승인은 행 생성·XLSX 쓰기 전에 거부하는 회귀 테스트를 통과한다. 결과를 잘라서 내보내지 않는다.

## 통합과 접근성

- [ ] 상세 분석에서 `/tools/supplier-review`로 이동하고 로고로 홈에 돌아갈 수 있다.
- [x] 데스크톱에서 Univer 비교 시트가 로드되며 키보드 편집을 시도해도 읽기 전용 값이 바뀌지 않는다.
- [ ] 페이지 이동·재진입 시 Univer 인스턴스 정리를 브라우저에서 확인한다.
- [ ] 입력·매핑·승인·다운로드 전체 흐름을 키보드만으로 수행하고 오류·로딩·빈 상태를 인지할 수 있다.
- [x] 390px 모바일 뷰포트 에뮬레이션에서 페이지 전체의 가로 넘침이 없다.
- [ ] 실제 모바일 기기에서 필요한 조작과 터치 동작을 확인한다.
- [x] `tsc --noEmit` 종료 코드 0, `npm run build` 종료 코드 0, 빌드 후 `npm test` 49개 통과·0개 실패를 확인했다. 정적 페이지 1,339개가 생성됐으며 `/tools/supplier-review` 경로가 빌드에 포함됐다.
- [ ] meta.json의 ID·repoPath와 commercial.json의 기존 v1 호환성을 최종 확인한다.

## 실증 주장

출처의 한 번의 소요시간을 평균·절감률로 바꾸지 않는다. 유료 실증 판정에는 합의 후 첫 실제 수금·같은 범위의 시간 개선·오류 비증가·담당자 검토가 모두 필요하다. 수금 없이 효용만 확인되면 업무 타당성 관찰로 기록한다. 구매자·자료 접근·가격·만족·재사용·재결제와 지원 비용은 별도로 확인하며 현재 입증된 것으로 쓰지 않는다.
