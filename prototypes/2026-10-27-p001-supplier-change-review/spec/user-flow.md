# User flow — 공급사 상품 변경 검수

## Happy path — 로컬 검수

프로젝트 상세에서 `/tools/supplier-review` 열기 → 기준 XLSX·CSV와 새 XLSX·CSV 선택 → 각 시트의 첫 비어 있지 않은 행을 헤더로 확인하고 SKU·비교 열 연결 → 정확한 SKU로 비교 → Univer 표에서 변경 값과 원본 행 확인 → 전달할 변경만 명시적으로 승인 → 승인한 항목의 XLSX 검수 목록 다운로드 → 파일을 열어 결과 재확인.

파일은 브라우저에서 처리하고 원본을 변경하지 않는다. 비교 화면은 읽기 전용이며 승인은 별도 명시적 조작으로 한다. 기본 승인 항목은 없다. 새 파일이나 매핑으로 비교를 다시 시작하면 이전 승인 상태는 폐기한다. 스토어 갱신은 이 흐름에 없다.

## Edge 1 — 식별자 예외와 한쪽에만 있는 상품

중복·빈 SKU는 원본 행과 이유를 표시하고 비교를 중단한다. SKU의 바깥 공백만 제거한 뒤 정확한 값으로 연결한다. 선행 0·상품명·옵션을 근거로 다른 SKU를 추정 연결하지 않는다. 한쪽에만 있는 행은 추가·제외 후보로 명시해 담당자가 검토한다. 제외 후보는 실제 단종·삭제를 증명하지 않으므로 자동 삭제로 처리하지 않는다.

## Edge 2 — 파일이나 비교 설정 변경

지원하지 않는 파일, 읽기 실패, 한 파일 5MiB·유효 시트 데이터 10,000행/100열·통합 문서 100만 셀·압축 해제 내용 50MiB 상한 초과는 이유를 알리고 다시 선택할 수 있게 한다. 상품 표가 아닌 보조 시트는 제외 이유를 경고하며 유효한 시트를 선택하게 한다. 시트·열 매핑을 바꾸면 비교 결과와 승인을 초기화한다. 비교 값의 바깥 공백은 제거하며 엑셀 숫자는 실제 저장값을 사용한다. 빈 값과 0, 통화·단위 정의가 다른 경우 담당자가 원본을 확인한다. 변경이 없으면 변경 없음 상태를 보여 주고 승인·다운로드를 유도하지 않는다.

## Edge 3 — 승인과 다운로드

아무 항목도 승인하지 않았으면 승인 결과 다운로드를 비활성화한다. 승인 취소는 결과에서 즉시 제외한다. 다운로드 실패 시 현재 검토 상태를 유지하고 재시도할 수 있게 한다. 내려받은 파일은 승인한 변경의 검수 목록이며 전체 상품 파일이나 Shopify 업로드 파일로 사용하도록 안내하지 않는다.

승인한 변경 필드가 100,000행을 넘으면 다운로드 파일을 만들기 전에 중단하고 이유를 표시한다. 승인 상태를 유지하므로 상품 승인을 일부 취소해 다시 내려받을 수 있다. 비교 열을 줄이는 경우에는 입력 설정 변경 규칙에 따라 다시 비교하고 승인한다. 초과한 결과를 잘라서 내려주지 않는다.
