# Falsification checklist (6)

1. If a user cannot explain why the score changed after moving one control, the model is too opaque.
2. If score does not rise directionally with higher severity or concentration, the heuristic is broken.
3. If different affected nodes produce nearly identical impacted tables, the prototype lacks decision-useful specificity.
4. If `1w` and `12m` scenarios look materially the same, horizon is not earning a dedicated control.
5. If the five impacted rows do not suggest concrete follow-up diligence, the output is too generic.
6. If an informed semiconductor investor finds the ticker mapping implausible, the segment library needs revision.
