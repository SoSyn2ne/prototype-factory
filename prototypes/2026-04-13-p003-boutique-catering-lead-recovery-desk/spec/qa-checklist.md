# QA checklist

## Happy path
- User can scan lead risk, open one event inquiry, and understand the booking blocker immediately.
- User can see whether delay comes from quote turnaround, menu choice, or venue coordination.
- User can prepare a polished next step from the same workspace.

## Edge cases
- Lead has no fixed event date yet.
- Multiple venues or menu packages are under discussion.
- Quote was sent, but response is stalled because of budget mismatch.

## Acceptance verification
- Meta and spec files stay aligned on audience, design profile, and UI sections.
- Product tone remains premium and service-oriented, not generic CRM software.
- Demo remains scaffold-level only with no custom production build implied.
