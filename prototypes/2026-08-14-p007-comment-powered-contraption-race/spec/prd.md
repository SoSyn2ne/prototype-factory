# PRD — Comment-Powered Contraption Race

## Problem
- Livestream viewers spend comments to build, jam, and rescue a ridiculous shared machine in sixty seconds.

## Target user
- Small livestream creators and friend groups wanting audience play without a complex game setup.

## Arrival path
- Search, community referral, or operator handoff at the trigger: crowd chaos / creator participation.

## Business / validation route
- Test core-flow completion and artifact sharing; validate a paid lightweight subscription, template pack, or qualified partner lead where appropriate.

## Core loop
- Host picks a silly delivery goal, viewers vote parts through comments, the machine snaps together live, sabotage events interrupt it, and the final crash/recovery becomes a share clip.

## First screen
- Communicate the one-liner in three seconds and expose the first action beside a realistic result preview.

## Key screens
- goal picker; comment command legend; live contraption canvas; team energy meters; sabotage/recovery cards; replay clip.

## Interaction rules
- One decisive primary action per state; preserve entered data; show loading, empty, success, blocked, and error states.

## Output artifact
- Spectacular failure and last-second rescue create a 10-second replay clip.

## Share / return loop
- Spectacular failure and last-second rescue create a 10-second replay clip.

## Constraints
- Time: one-session prototype.
- Budget: realistic local mock data; no paid external API.
- Platform: responsive web, desktop and mobile.

## Non-goals
- Production integrations, legal guarantees, payments, or a custom Phase A demo.

## Success metrics
- First action understood in 3 seconds; core flow completed without instruction; output shared or saved.

## QA / screenshot criteria
- Profile playful-experimental is unmistakable; primary interaction and result fit above fold; mobile has no overflow; all required sections are visible.
