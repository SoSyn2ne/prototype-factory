# Falsification checklist (5–7)

1. Do operators already rely on CLI tools and refuse a browser UI during incidents?
2. Are the most common failures actually *not* covered by these signals (e.g., kernel/driver panics)?
3. Does a checklist feel like busywork when urgency is high?
4. Is “incident mode freeze” confusing (operators expect live metrics)?
5. Does report generation get ignored because incidents are resolved before writing anything down?
6. Would a notification system be required before this UI provides value?
7. Would real data integration take too long vs. just improving scripts/alerts?
