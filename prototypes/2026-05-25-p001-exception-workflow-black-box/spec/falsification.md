# Falsification checklist (5-7)

1. Does the prototype avoid being a renamed version of recent PF dashboards/planners?
2. Can a new viewer understand the trigger and target user without explanation?
3. Is the assigned design profile (operator-dense) visible in density, palette, hierarchy, and interaction tone?
4. Does the primary workflow center on: The owner replays a real messy week through event cards, captures exception decisions, then receives a workflow map, automation readiness score, kill-list, and first safe automation brief.
5. Are signal references (S1, S2, S8) represented as problem evidence rather than market-size claims?
6. Are the required UI sections present without burying the main action?
7. Would the user have a reason to save, share, export, or pay after completing the workflow?
