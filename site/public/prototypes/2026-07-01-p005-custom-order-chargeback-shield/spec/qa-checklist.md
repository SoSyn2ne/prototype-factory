# QA checklist

## Happy path
- First screen communicates: Do not wait until the bank sides with the buyer to start building the court case.
- User can identify the target user and trigger within 3 seconds.
- User can complete the primary mechanic: boundary receipt builder.
- Prototype produces: Buyer boundary receipt and chargeback evidence packet..

## Edge cases
- Empty input state explains what proof/data is needed.
- User with partial evidence can still get a next step.
- Mobile layout keeps key actions reachable.
- Copy avoids claiming legal, medical, insurance, or financial guarantees.

## Acceptance verification
- Design profile appears exactly once as operator-dense.
- Required sections are present: Order risk intake, Approval milestone checklist, Delivery proof vault, Buyer boundary receipt, Dispute evidence export.
- Stitch prompt cites signals S13, S14 as problem evidence only.
- No custom demo is implemented during Phase A.
