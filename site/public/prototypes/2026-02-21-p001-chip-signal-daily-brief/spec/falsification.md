# Falsification checklist (5–7)

1. **Time-to-value fails:** If a user can’t reliably read and decide in ≤5 minutes, the format is too heavy and will be abandoned.
2. **Tripwires don’t change behavior:** If after 2–4 weeks the user reports the brief didn’t prevent *any* avoidable mistake (missed earnings, panic trade, ignoring a major event), the core mechanism isn’t working.
3. **Too many false alarms:** If >30% of fired tripwires feel like “noise” or lead to regretful actions, the system needs fewer/stricter triggers.
4. **No unique insight vs. existing newsletters:** If users say “this is the same as what I already get from (newsletter/app)”, then the differentiator (tripwire + next action + uncertainty labels) isn’t strong enough.
5. **Uncertainty labels don’t build trust:** If users ignore or dislike KNOWN/ASSUMPTION/UNKNOWN tagging (or it doesn’t reduce arguments about correctness), the labeling adds friction without benefit.
6. **Maintenance burden too high:** If maintaining sources/rules takes >10 minutes/day or requires constant manual fixes, it won’t scale as a daily factory.
7. **Rules are un-actionable:** If recommendations frequently end as “it depends” without a concrete next action (hold/add/trim/alert), then the product fails its purpose.
