# PRD — Camp Slot Panic Board

## Problem
- A working-parent command board that compares summer camp slots, true weekly cost, deadlines, waitlist risk, and coverage gaps before school breaks explode.
- Inspired by external problem signals: Signal 5 — Reddit r/Parenting — summer camp/daycare cost shock: https://www.reddit.com/r/Parenting/comments/1kvnddb/daycare_in_2025/; Signal 6 — Reddit r/Parenting — waitlists and sold-out camp anxiety: https://www.reddit.com/r/Parenting/comments/1jewgd8/the_cost_of_childcare_is_beyond_ridiculous/

## Target user
- Working parents and caregivers juggling school breaks, multiple children, camp registration windows, and childcare budgets.

## Key UX
- Enter child ages, school-break weeks, commute limits, budget, and known camps; see sold-out risk, true weekly costs, coverage gaps, sibling conflicts, and a registration attack plan.

## Required UI sections
- school-break coverage calendar
- camp slot watchlist
- true weekly cost calculator
- waitlist and sold-out risk flags
- sibling logistics conflict board
- registration deadline sprint
- backup-care SOS plan

## Design profile
- calm-consumer

## Theme
- 사교육

## Stitch prompt
Design a responsive parent-planning product called Camp Slot Panic Board for working parents trying to secure summer camp and school-break childcare before slots disappear. Users should enter child ages, school-break weeks, commute radius, budget, sibling constraints, and known camps, then compare true weekly cost, activity add-ons, deposit deadlines, waitlist risk, and coverage gaps. Include a school-break coverage calendar, camp slot watchlist, true weekly cost calculator, waitlist and sold-out risk flags, sibling logistics conflict board, registration deadline sprint, and backup-care SOS plan. Design direction: use a calm-consumer aesthetic with soft daylight colors, reassuring cards, gentle urgency states, family-calendar visuals, and clear next-step buttons so stressed parents feel organized instead of judged.

## Constraints
- Time: Phase A scaffold only; Stitch export expected later.
- Budget: Keep prototype static and fast to review.
- Platform: Web demo imported from Stitch in later phase.

## Non-goals
- No full custom implementation in Phase A.
- No external LLM/API calls.

## Success metrics
- User understands the core pain within 5 seconds.
- Main workflow has one obvious next action.
- Stitch output can preserve the original environment for `/d/2026-05-05-p003` in Phase B/C.
