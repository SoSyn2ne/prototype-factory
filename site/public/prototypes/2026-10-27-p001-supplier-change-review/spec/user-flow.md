# User flow — 공급사 상품 변경 검수

## Happy path — 향후 실증
원문 문제 확인 → 운영자 동의·파일 정의 확인 → 익명 파일 한 쌍과 수작업 기준 확보 → 식별자/열 연결 확인 → 변경·변경 없음·예외를 분리 → 담당자가 원본 행과 대조 → 전달할 검수 목록과 수동 처리 절차를 승인한다. 초기에는 전 과정을 수작업으로 해도 된다.

## Edge 1 — 식별자 불일치
중복·누락·선행 0 손실·다른 옵션이 보이면 자동 연결하지 않는다. 해당 행은 미해결로 분리하고 담당자 판정 전 변경 목록으로 넘기지 않는다. 신뢰할 최신 내보내기가 없으면 대조 자체를 보류한다.

## Edge 2 — 정의·형식 변경
열 이름·통화·단위·빈 값 의미가 달라졌다면 먼저 정의를 확인한다. 이전 규칙으로 밀어 넣지 않고 원본을 보존한 채 기존 수동 작업으로 돌아간다. 현재 web/index.html에는 파일 선택·처리·승인 기능이 없으며 미리 작성한 예시만 읽는다.
