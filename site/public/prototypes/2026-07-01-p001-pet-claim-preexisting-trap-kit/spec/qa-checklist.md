# QA checklist

## Happy path
- First screen communicates: Your $25,000 claim should not die because one vague note looked like a preexisting condition.
- User can identify the target user and trigger within 3 seconds.
- User can complete the primary mechanic: vet-record evidence interrogation.
- Prototype produces: PDF-style appeal packet with timeline, record checklist, and insurer letter..

## Edge cases
- Empty input state explains what proof/data is needed.
- User with partial evidence can still get a next step.
- Mobile layout keeps key actions reachable.
- Copy avoids claiming legal, medical, insurance, or financial guarantees.

## Acceptance verification
- Design profile appears exactly once as calm-consumer.
- Required sections are present: Claim denial intake, Vet timeline builder, Preexisting-clause explainer, Missing-record request checklist, Appeal letter preview.
- Stitch prompt cites signals S1, S2, S3 as problem evidence only.
- No custom demo is implemented during Phase A.
