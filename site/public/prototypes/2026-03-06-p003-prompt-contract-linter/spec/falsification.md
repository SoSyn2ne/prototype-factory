# Falsification checklist (5–7)

1. If reviewers cannot distinguish high-risk from low-risk prompts better than chance after using this tool, is the concept invalid?
2. If ambiguous language flags are mostly perceived as noise (>50% false positive feedback), does the linter fail its core value proposition?
3. If required constraints vary so widely by team that no baseline rule set is broadly useful, should this product be abandoned or repositioned?
4. If users ignore rewrite snippets and still need manual expert help for every fix, does the tool provide enough practical leverage?
5. If risk score does not correlate with real incident likelihood in pilot prompts, should scoring be removed from MVP?
6. If offline heuristic rules cannot catch critical unsafe patterns found in retrospective incidents, is this approach fundamentally insufficient?
