# QA 체크리스트 — 월마감 누락 서류 점검

## 현재 설계 확인

- [ ] meta.json의 ID·날짜·repoPath와 commercial.json의 projectId가 일치한다.
- [ ] 두 운영자 글과 2026-10-27 확인일, 정확한 게시일 미확인이 명시돼 있다.
- [ ] 같은 글의 댓글을 별도 독립 출처로 세지 않는다.
- [ ] 포털 자료 수집 문제와 이 제안의 목록 대조 범위를 분리한다.
- [ ] HTML에 `설계 예시 · 실제 파일 처리 미구현`이 보인다.
- [ ] 실제 업로드·대조·다운로드·발송 기능이나 가짜 버튼을 두지 않는다.
- [ ] 표의 합성 고객·닫힌 월·대조 근거와 요청 초안이 서로 일치한다.
- [ ] 누락 요청과 검토 필요 확인 질문을 구분하고 수신 확인을 마감 완료로 표현하지 않는다.
- [ ] 확정 고객·가격·결제·절감액·반복 사용·재결제를 만들지 않는다.

## 실제 프로그램 구현 후 검증 — 현재 미실행

- [ ] 한 사무소·닫힌 한 달의 승인된 익명 기준표와 수신 목록을 확보한다.
- [ ] 다른 고객·다른 월·모호한 이름·수정본/중복이 수신 확인으로 잘못 분류되지 않는다.
- [ ] 필요한데 없는 자료를 수신 확인으로 표시한 사례가 0건이다.
- [ ] 모든 상태에 목록상 근거 또는 검토 이유가 있다.
- [ ] 필수 목록 미정·수신 목록 없음·지원하지 않는 입력·읽기 오류를 구분한다.
- [ ] 원본 파일을 변경·삭제·전송하지 않고 포털·은행 자격증명을 받지 않는다.
- [ ] 요청 문구는 초안이며 담당자가 승인·수정한 뒤 직접 기존 채널에서 처리한다.
- [ ] 같은 사례에서 준비·대조·추적·검토 시간을 각각 측정하고 포털 다운로드 시간은 분리한다.
- [ ] 예외·교육·지원 원가와 고객이 합의한 가격·한도를 비교한다.
- [ ] 만족·첫 결제·반복 사용·재결제를 각각 확인한다.

## 시각 확인 — 브라우저 검토 필요

- [ ] 390px와 1440px에서 예시 표시·고객·대상 월·상태가 읽힌다.
- [ ] 표 캡션·열 제목과 상태 텍스트가 있고 색상 없이도 이해된다.
- [ ] 키보드로 실제 링크에 접근하고 로컬 문서·출처 링크가 올바르다.
- [ ] 가짜 처리 결과나 실제 파일을 분석했다는 문구가 없다.
