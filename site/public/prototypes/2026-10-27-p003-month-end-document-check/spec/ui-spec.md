# UI 명세 — 월마감 누락 서류 점검

## 화면 목적

담당자가 고객·대상 월별로 어떤 서류가 확인됐고 무엇을 요청하거나 다시 봐야 하는지 읽는다.
첫 화면은 작업 목록과 근거이며 별도의 소개 페이지·매출 지표·확신 점수는 없다.

## 현재 범위

읽기 전용 `web/index.html`의 고정된 합성 자료다. 상단과 요청 초안에
**설계 예시 · 실제 파일 처리 미구현**을 표시한다. 실제 자료 수신·대조·다운로드·발송은 구현하지 않는다.
입력창·업로드 영역·실행/발송 버튼처럼 작동을 암시하는 장식은 넣지 않는다.

## 구성

1. 제목과 예시 표시, 고객 별칭·닫힌 월·합성 자료 설명
2. 필수 서류·상태·대조 근거의 표. 색상 없이도 상태 문구로 판별 가능
3. 요청 초안: 목록 기준 누락 요청과 검토 필요 확인 질문을 분리
4. 범위: 수신 확인은 자료 적정성·마감 완료가 아님, 담당자 검토 필요
5. PRD·QA·원문 출처 링크

## 고정 예시 자료

| 필수 항목 | 예시 상태 | 근거 |
| --- | --- | --- |
| 은행 명세서 · 운영계좌 가 | 수신 확인 | `고객가_2026-09_은행가.pdf`의 고객·월·종류 매핑 승인 |
| 매출 자료 | 수신 확인 | `고객가_2026-09_매출.csv`의 고객·월·종류 매핑 승인 |
| 은행 명세서 · 운영계좌 나 | 누락 | 승인된 수신 목록에 일치 항목 없음 |
| 카드 명세서 · 카드 가 | 검토 필요 | `카드A_확인필요.pdf`의 대상 월 매핑 미승인 |

## 구현 후에 필요한 상태

- 기준 목록 미작성: 대조 시작을 보류하고 담당자에게 필수 항목 확정 요청
- 수신 목록 없음: 실제 미수신을 단정하지 않고 목록 미제공으로 표시
- 다른 월·모호한 이름·중복·충돌: 검토 필요, 추정한 완료 없음
- 지원하지 않는 입력·읽기 오류: 원본 보존, 실패 이유, 기존 수동 방식 안내
- 정상 결과: 근거 포함 상태표, 요청 초안, 최종 사람 검토

## 시각·접근성

중립 표면과 한 가지 강조색, 일관된 8px 모서리와 1px 경계를 쓴다.
한국어 시스템 글꼴과 명확한 제목·표 머리글·캡션·링크를 제공한다.
좁은 화면에서는 표 영역만 수평 스크롤하며 문서 본문은 화면 안에서 줄바꿈한다.
정적 예시에는 로딩 애니메이션이나 가짜 성공 알림을 넣지 않는다.
