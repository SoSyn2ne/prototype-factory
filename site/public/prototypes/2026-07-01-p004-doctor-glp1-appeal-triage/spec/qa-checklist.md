# QA checklist

## Happy path
- First screen communicates: Doctors are tired of writing doomed GLP-1 appeals one inbox message at a time.
- User can identify the target user and trigger within 3 seconds.
- User can complete the primary mechanic: criteria matcher.
- Prototype produces: Patient message plus appeal-document checklist and chart-note snippet..

## Edge cases
- Empty input state explains what proof/data is needed.
- User with partial evidence can still get a next step.
- Mobile layout keeps key actions reachable.
- Copy avoids claiming legal, medical, insurance, or financial guarantees.

## Acceptance verification
- Design profile appears exactly once as operator-dense.
- Required sections are present: Patient request queue, Plan criteria matcher, Appeal viability badge, Message template library, Documentation needed checklist.
- Stitch prompt cites signals S10, S11, S12 as problem evidence only.
- No custom demo is implemented during Phase A.
