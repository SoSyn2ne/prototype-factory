# Assumptions (KNOWN / ASSUMPTION / UNKNOWN)

## KNOWN
- Margin leakage is the core value story, not generic ticket management.
- Users need to balance customer satisfaction against unit economics on each case.
- A single desktop screen should make the next action obvious within seconds.

## ASSUMPTION
- Teams already have baseline return policy rules and need an operations layer above them.
- Suggested save offers can be understood without showing full backend policy logic.
- Most morning triage happens on desktop, not mobile.

## UNKNOWN
- How much historical customer behavior needs to be visible on the first screen.
- Whether users prefer queue-first or analytics-first layout weighting.
- What threshold makes a policy exception feel worth interrupting the flow.
