# PRD — Subscription Cancellation Proof Locker

## Problem
- A consumer receipt vault that turns hidden cancellation paths, chats, emails, and recurring charges into refund-ready proof.
- Search/community evidence suggests this is a live pain, not a generic dashboard rename.

## Target user
- Consumers, parents managing household subscriptions, cord-cutters, app subscribers, and people trying to stop recurring charges without losing evidence.

## Key UX
- Enter a subscription, signup channel, charge history, renewal date, cancellation steps, screenshots, support chats, and card-dispute status; build a timeline, detect dark-pattern friction, store proof, draft refund requests, and remind users to verify the next statement.

## Required UI sections
- subscription intake
- cancellation journey timeline
- screenshot and chat evidence vault
- renewal and statement watchlist
- refund request composer
- card-dispute packet
- household recurring-charge map

## Design profile
- `calm-consumer` — reflected in the Stitch prompt and visual direction.

## Stitch prompt
Design a calm consumer finance product called Subscription Cancellation Proof Locker for consumers, parents managing household subscriptions, cord-cutters, app subscribers, and people trying to stop recurring charges without losing evidence. Users should enter a subscription, signup channel, charge history, renewal date, cancellation steps, screenshots, support chats, and card-dispute status, then build a timeline, detect dark-pattern friction, store proof, draft refund requests, and remind users to verify the next bank or card statement. Include a subscription intake, cancellation journey timeline, screenshot and chat evidence vault, renewal and statement watchlist, refund request composer, card-dispute packet, and household recurring-charge map. Design direction: use a calm-consumer aesthetic with soft money-saving colors, friendly progress steps, large renewal dates, reassuring evidence cards, and plain-language refund scripts so the product feels like a patient financial advocate, not a hostile chargeback console.

## Constraints
- Time: Phase A spec/scaffold only; do not implement custom demo yet.
- Budget: Use Stitch export workflow for Phase B.
- Platform: Web prototype, desktop-first unless consumer flow benefits from responsive cards.

## Non-goals
- Do not claim legal, medical, tax, or financial certainty.
- Do not integrate live paid APIs in Phase A.

## Success metrics
- A user understands the painful trigger within 5 seconds.
- The main workflow is clear from intake to export/share/action.
- The UI can be built from the Stitch prompt without additional explanation.
