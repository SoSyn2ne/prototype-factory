# Falsification checklist (5–7)

1. Does the ruleset misclassify too often (users disagree with the category) on real incidents?
2. Are the suggested next steps too generic to be actionable?
3. Does the UI take longer than just Googling the error line?
4. Do users avoid pasting logs due to privacy/security concerns?
5. Does the tool encourage cargo-cult fixes (e.g., “reboot” first) rather than careful diagnosis?
6. Does the incident note feel redundant with existing issue trackers?
7. Are the categories missing a common class (filesystem full, network dataset fetch, permission)?
