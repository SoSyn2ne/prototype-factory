# Falsification checklist

1. The first screen reads like a generic dashboard instead of claim evidence pack + response composer.
2. A target user cannot identify the next action within 5 seconds.
3. The required UI sections are missing: Case intake: order, claim type, deadline; Evidence autobox with required/missing proof; Timeline builder from tracking and messages; Platform policy snippet drawer; Dispute response and review-risk script.
4. The design direction does not match operator-dense.
5. The prototype depends on source claims as market-size proof instead of treating them as problem evidence.
6. The workflow duplicates one of the last 7 PF batches without a new user, trigger, data source, or interaction mechanic.
7. The final screen lacks a shareable output, packet, receipt, or result tied to: The dispute packet can be shared in seller groups as a before/after proof template.
