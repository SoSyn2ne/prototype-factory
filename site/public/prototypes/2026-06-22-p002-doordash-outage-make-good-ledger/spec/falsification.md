# Falsification checklist (5–7)

1. Show outage ledger to a restaurant operator; reject if it feels like a generic incident board.
2. Confirm affected-order rows connect to refund, make-good, and support claim states.
3. Verify mobile/tablet controls are large enough for shift use.
4. Reject if driver missed-pay lane is vague or visually secondary.
5. Test whether a user can export a claim summary from synthetic data in under 5 minutes.
6. Reject if the prototype implies guaranteed reimbursement.
7. Confirm the first screen shows "platform failed but proof is needed" immediately.
