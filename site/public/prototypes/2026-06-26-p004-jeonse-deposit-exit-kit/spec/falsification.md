# Falsification checklist (5-7)

1. Does the first screen solve the trigger moment instead of becoming a generic dashboard?
2. Are the cited source signals visible in sample data and workflow language?
3. Does the assigned design profile (calm-consumer) clearly shape layout, density, and controls?
4. Is there a concrete output artifact the user would share or act on?
5. Is the theme (자산 방어) visible without theme-washing the idea?
6. Would the target user recognize their current workaround in the product?
7. Does the Stitch prompt avoid custom implementation instructions outside Phase A?

## Stitch prompt under test
Build a production-grade web app prototype called "Jeonse Deposit Exit Kit" for Korean tenants and foreign residents preparing to recover a large rental deposit. The first screen must be a working proof kit with deposit risk countdown, fixed-date/address registration checklist, registry and lien snapshot tray, landlord message timeline, HUG guarantee stepper, move-out inspection drawer, and escalation letter packet. Use realistic sample data: KRW 180M jeonse deposit, lease ending in 47 days, fixed date complete, landlord delay message, registry update needed, HUG question, and move-out photo checklist. Design direction: use the calm-consumer profile with reassuring legal-adjacent guidance, low-stress warm neutrals, plain-language recovery states, and one gentle action accent for packet completion. Do not make a marketing landing page; the first screen must be the working app.
