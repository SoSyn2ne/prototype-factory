# Falsification checklist — Prior Auth Appeal Packet Builder

1. Does the target user recognize their exact triggering pain from the first screen?
2. Is this meaningfully different from the last 7 PF batches, not just a renamed dashboard/rescue/planner?
3. Is the assigned design profile (operator-dense) visible in layout, density, color, and interaction style?
4. Does the key UX produce a concrete artifact users would act on, save, export, or share?
5. Are the cited signals visible as problem evidence without pretending to prove market size?
6. Can Stitch express the workflow with static sample data and no integrations?
7. What evidence would show this is too narrow, too risky, or not monetizable?
